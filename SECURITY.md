## Известные риски

Эти ограничения — **осознанные решения**, а не недосмотры. Здесь описано, что
именно они означают.

### 1. Эндпоинт Google Apps Script не аутентифицирован 🔴

Заявка уходит `POST`-ом на URL вида
`https://script.google.com/macros/s/AKfycb…/exec`. Этот URL виден любому,
кто открыл исходник страницы.

**Риск:** любой посетитель (и любой бот) может отправить произвольные данные
в вашу таблицу, заполнив её мусором. Данные при этом остаются в вашей
таблице — утечки к злоумышленнику нет, но таблица засоряется.

**Важно понимать:** скрыть URL в статическом сайте невозможно — браузер видит
всё. Публикация под ключом в клиентском коде не даёт защиты.

**Особенность Apps Script, о которой легко забыть:** `/exec` не отвечает
сразу — он возвращает `302` на
`https://script.googleusercontent.com/macros/echo?user_content_key=…`, и уже
оттуда приходит результат выполнения. Домен `script.googleusercontent.com`
обязан быть разрешён в `connect-src`, иначе браузер блокирует редирект,
`fetch` падает с `TypeError: Failed to fetch`, и посетитель видит
«Ошибка отправки» при полностью рабочем скрипте.

**Что можно сделать:**

| Мера | Сложность | Что даёт |
|---|---|---|
| Принимать заявку через форму на своём сервере | средняя | Полный контроль: rate-limit, капча, валидация |
| Cloudflare Workers / Vercel Edge Function перед Apps Script | низкая | Проверка Origin/Referer, rate-limit по IP |
| Google Apps Script + проверка `e.parameter` и капчи reCAPTCHA | низкая | Отсекает ботов, но URL остаётся публичным |
| Ограничить «Кто имеет доступ: любой» и выдавать ссылку вручную | нет | Не защищает — URL всё равно в исходнике |
| Принимать заявки только по телефону (`tel:`), убрать форму | нет | Полностью убирает вектор; теряете заявки с сайта |

Текущее состояние: **вектор принят осознанно**. Рекомендуемая следующая
ступень — Cloudflare Worker с rate-limit перед Apps Script.

### 2. Персональные данные в `localStorage` демо-режима 🟡

Если `CONFIG.googleScriptUrl` пуст, заявка (имя, телефон, адреса) сохраняется
в `localStorage` браузера.

**Риски:**
- данные остаются в браузере, доступны любому скрипту на этом домене;
- на общем компьютере следующий пользователь может прочитать их через DevTools.

**Что сделано:** записи старше `CONFIG.demoOrdersTtlDays` (по умолчанию 1 сутки)
удаляются при следующей попытке отправки. В боевом режиме (когда Apps Script
подключён) `localStorage` **не используется вообще**.

**Раскрыто** в `privacy.html`, разделы 03 и 06.

### 3. CSP задан мета-тегом, а не заголовком 🟡

Политика безопасности лежит в `<meta http-equiv="Content-Security-Policy">`,
потому что GitHub Pages не позволяет задавать произвольные HTTP-заголовки.

**Что из-за этого не работает:**

| Директива | Статус в `<meta>` | Почему важно |
|---|---|---|
| `frame-ancestors` | ❌ игнорируется | Защита от кликджекинга. Сейчас страницу можно встроить в `<iframe>` на чужом домене |
| `sandbox` | ❌ игнорируется | Изоляция документов |
| `report-uri` / `report-to` | ❌ игнорируется | Нет отчётов о нарушениях CSP |

Всё остальное (`script-src`, `style-src`, `img-src`, `connect-src`, `frame-src`,
`object-src`, `base-uri`, `form-action`) — работает штатно.

**Как закрыть `frame-ancestors`:** перенести сайт за Cloudflare (Pages/Workers)
или другой хостинг, где можно задать
`Content-Security-Policy: frame-ancestors 'none'` заголовком.

### 4. Внешние сервисы получают часть данных 🟡

При заполнении формы идёт запрос к `nominatim.openstreetmap.org`
(проверка адреса). Теряется текст, который пользователь ввёл в поля
адреса. Google Fonts, Яндекс.Карты и Яндекс.Метрика (если включена) —
тоже внешние.

Перечень с указанием стран размещения серверов приведён в `privacy.html`,
раздел 07.

### 5. Порядковые номера заявок предсказуемы 🟢

Номер вида `MS-1234` генерируется через `Math.random()` и не является
ни секретом, ни идентификатором — он служит только для подтверждения
пользователю. Реальной защиты от перебора не требуется: данные
не возвращаются по номеру.
